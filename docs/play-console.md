## 1. Контент приложения (Политика → Контент приложения / Policy → App content)

На главной панели приложения есть список «Настройте приложение» — это те же пункты. Проходи сверху вниз, после каждого «Сохранить».

1. **Политика конфиденциальности** → `https://mindkeep.cloud/privacy`.
2. **Доступ к приложению (App access)** → «Все функции или некоторые из них ограничены» → «Добавить инструкции»:
   - Название: `Demo account`
   - Имя пользователя: `demo@mindkeep.cloud`, пароль: пароль демо-аккаунта
   - Другие сведения: `After the password the app asks for a one-time code. For this account the code is always <6 digits from REVIEW_LOGIN_CODE>.`
3. **Реклама (Ads)** → «Нет, в приложении нет рекламы».
4. **Возрастные ограничения (Content rating)** → «Начать анкету»: email `contact@mindkeep.cloud`, категория **«Утилиты, инструменты повышения производительности, средства связи и другое»**; на все вопросы о контенте — **Нет**; «Пользователи взаимодействуют или обмениваются контентом» — **Нет**; «Цифровые покупки» — **Нет**. Ожидаемо: Everyone / PEGI 3 / USK 0.
5. **Целевая аудитория (Target audience)** → **18 лет и старше** (можно добавить 13–17). **Не выбирать младше 13** — иначе применяется политика для семей.
6. **Новостное приложение** → Нет.
7. **Безопасность данных (Data safety)** → по таблице в `store-listing.md` → «Google Play Data safety». Ключевое: данные собираются, **не передаются** третьим лицам; шифрование при передаче — да; удаление — да, ссылка для удаления аккаунта: `https://mindkeep.cloud/delete-account`; фото — **собираются, необязательно, обрабатываются временно (ephemeral)**, цель — функциональность.
8. **Государственные приложения** → Нет.
9. **Финансовые функции** → «Моё приложение не предоставляет финансовых функций» (личный бюджет — это учёт, а не финансовая услуга).
10. **Приложения для здоровья (Health apps)** → отметить **«Питание и контроль веса»** и **«Отслеживание активности и фитнеса»**; это не медицинское устройство.
11. **Рекламный идентификатор (Advertising ID)**, если спросят → «Нет, приложение не использует рекламный идентификатор». Если Play пожалуется, что в сборке есть разрешение `AD_ID`, — напиши, заблокируем его в `app.json` и пересоберём.

## 3. Закрытое тестирование (Тестирование и выпуск → Тестирование → Закрытое тестирование)

Для личного аккаунта Google требует **закрытый тест: не меньше 12 тестировщиков 14 дней подряд**, и только потом можно подать заявку на продакшен.

1. **Закрытое тестирование → «Создать трек»** (или использовать готовый «Alpha»).
2. **Страны/регионы** → выбрать все (или те, где живут тестировщики). DSA у Google — отдельный вопрос: если Play попросит статус трейдера для ЕС, ответить по аккаунту (личный, без монетизации в Play).
3. **Тестировщики → «Создать список адресов»** → название `MindKeep testers` → вставить Gmail тестировщиков (15–20, через запятую или по строкам) → сохранить и **отметить список галочкой**. Поле «Ссылка для отзывов»: `contact@mindkeep.cloud`.
4. **«Создать выпуск»**:
   - Подписание приложений Google Play — «Использовать ключ, созданный Google» (по умолчанию).
   - Загрузить AAB 1.0.3 (5), скачанный из EAS.
   - Название выпуска: `1.0.3 (5)`.
   - Примечания: `<en-US>First test release: tasks, habits, 3·7·30 reviews, nutrition, notes and budget.</en-US><ru-RU>Первая тестовая версия: задачи, привычки, повторения 3·7·30, питание, заметки и бюджет.</ru-RU>`
5. **«Далее» → «Сохранить» → «Отправить на проверку»** (Send for review / Start rollout). Первая проверка Google — от нескольких часов до пары дней.
6. После одобрения на вкладке **«Тестировщики»** появится **ссылка «Присоединиться в интернете»** (opt-in link). Её — во второе письмо тестировщикам (тексты приглашений — в истории проекта / у владельца).

## 4. Две недели теста

- В Play Console (Закрытое тестирование → Тестировщики) видно, кто принял приглашение. Нужно **≥ 12 человек всё время**, лучше 15–20.
- Примерно на 7–10 день — **выпустить обновление** (новый AAB с исправлениями по отзывам, versionCode +1): это показывает Google, что тест настоящий.
- Собирать отзывы тестировщиков — пригодятся для анкеты.

## 5. Заявка на продакшен

Главная панель → **«Подать заявку на доступ к продакшену»** (Apply for production) — появится после 14 дней. Анкета: как набирали тестировщиков, что они проверяли, что исправили, насколько приложение готово. Отвечать по факту; черновик ответов поможет подготовить Claude.

После одобрения: **Продакшен → Создать выпуск** → тот же или новый AAB → страны → отправить на проверку → выпуск.

## Команды (из `mobile/`)

```text
npx -y eas-cli@latest build -p android --profile production   # новый AAB, versionCode +1 (закоммитить app.json)
npx -y eas-cli@latest build -p android --profile preview      # APK для установки напрямую
```

Загрузка в Play пока вручную через браузер (для `eas submit -p android` нужен ключ сервисного аккаунта Google Play — можно настроить позже).
